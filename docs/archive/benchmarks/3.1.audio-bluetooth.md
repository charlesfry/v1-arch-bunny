# Phase 3 checkpoint — audio + Bluetooth added

Measured 2026-08-19 on `bunne-test`, ~2 minutes after a fresh boot into **tty1
with no desktop started**. That makes it directly comparable to
[`2.1.base.md`](2.1.base.md), which also had no desktop running — Hyprland is
*installed* here but was not launched.

Captured with `~/t-benchmark` on the laptop.

## Headline: audio and Bluetooth cost ~6 MB at idle

**Idle RAM 595 MB**, against the base checkpoint's 599 MB. Within noise —
effectively unchanged despite adding a full audio stack and a Bluetooth daemon.

The reason is that only one of the two actually runs when idle:

| | idle cost | why |
|---|---|---|
| Audio (pipewire, wireplumber, pipewire-pulse) | **0 MB** | socket-activated; `wireplumber.service` is `WantedBy=pipewire.service`, so nothing starts until a client connects to `pipewire.socket` |
| Bluetooth (`bluetoothd`) | **6.0 MB** | a real resident daemon, started at boot |

Audio's warm cost, once something touches it, was measured separately at
**34.9 MB** (wireplumber 22.9 + pipewire 12.0). See `CHOICES.md` `audio`.

## SSH inflation — both checkpoints, ~27 MB each

`sshd` is in these numbers and **should not be**: `CHOICES.md`'s `ssh` row ships
`sshd.service` **disabled by default**, and the test laptop is an explicit
deviation so Claude can run diagnostics. Every checkpoint so far has measured a
daemon BunnE does not ship.

Measured cost: the listener is **7.5 MB** always-on, and each connection adds
**~21 MB** (an `sshd-session` pair).

During this run a connection was **sitting at the password prompt, never
authenticated** — costing 26.9 MB (`sshd` 7.4 + `sshd-session` 10.9 +
`sshd-auth` 8.6). Three independent signs agree: `sshd-auth` is OpenSSH's
*pre-authentication* process and exits once auth succeeds (a later measurement
with two authenticated sessions showed `sshd-session` pairs and **no**
`sshd-auth`); the journal has no `Accepted publickey` between boot and the run;
and only 2 logind sessions existed, because logind creates one only after
successful auth.

| | reported | SSH inflation | adjusted |
|---|---|---|---|
| `2.1.base` | 599 MB | ~28 MB (one session) | ~571 MB |
| this run | 595 MB | ~27 MB (half-open) | ~568 MB |

**So the 599 → 595 comparison is sound** — both were inflated by nearly the same
amount. That was luck, not method. `t-benchmark` now reports sshd process count
and RSS explicitly so it can be subtracted rather than hoped away.

## How to read `free`'s "used"

**~260 MB of the reported figure is not consumption.** `procps` 4.x computes the
`used` column as `MemTotal - MemAvailable`, which folds in the kernel's watermark
reserve and the cache it will not promise to free — the columns do not even sum
to `MemTotal`. By the classic `Total-Free-buffcache` definition, real usage here
is **328.6 MB**:

| | | |
|---|---|---|
| Slab | 100 MB (81 unreclaimable) | btrfs metadata, dentry/inode caches |
| VmallocUsed | 85 MB | kernel virtual allocs — 196 modules, 47.5 MB of module text (`nvidia` 17.4, `i915` 5.1) |
| KernelStack + PageTables + Percpu | 12.7 MB | per-task kernel overhead |
| processes | ~190 MB RSS | overcounted: shared libraries counted per-process |

**Consequence for priority 2:** there is a floor near 300 MB on this hardware —
kernel, modules, slab — that no daemon-trimming can reach, and both NVIDIA and
btrfs push it up. The part BunnE actually controls is the process column, ~150 MB
at TTY idle once sshd is excluded. Judge the project on that, not on the total.
`t-benchmark` now prints both definitions.

## Known gaps in this run

- The snapshot count printed `0` rather than skipping: `sudo -n btrfs subvolume
  list /` failed, but the `|| echo` never fired because the failure was swallowed
  by the pipe into `wc -l`. No snapshot data was captured. Fix the script before
  the next checkpoint — `snapshot-bloat` is one of the three headline gripes and
  wants a trend line.
- Nothing here exercises the compositor. Hyprland is installed but unlaunched, so
  this says nothing about the cost of a running desktop.

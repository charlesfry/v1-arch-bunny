# 4.10 — kitty on the 4090 desktop (informational, NOT DA-gated)

`omarchy` desktop (24-core AMD, RTX 4090, nvidia 610.57.04, Hyprland
0.56.2), 2026-08-24 ~10:24, load 0.01-0.08, author present (he installed
kitty himself and ran the instrument twice first — all package changes on
this machine are his alone). Instrument: `instruments/spawnbench-hypr.py`
(Hyprland-socket port of spawnbench v2; spawn via command socket,
`openwindow` event as the milestone). Raw: `raw/4.10.kitty-4090-hypr.jsonl`.

Provisional per the ledger's informational precedent: single boot, one
session, different machine AND compositor AND milestone than every 4.x
number — quote it as context, not as a cross-row comparison. Gate it
through DA if it ever feeds a `CHOICES.md` row.

| arm (blocks interleaved D-N-D-N, n=8 warm/arm) | warm medians |
|---|---|
| kitty (default: glvnd enumerates nvidia + mesa) | 67.6 / 67.3 |
| kitty pinned nvidia-only (mesa ICD removed) | 67.6 / 67.8 |

Run-0 "colds" 66.3-67.2 are warm-cache colds (kitty had run minutes
before), not boot-colds.

Two takeaways:

1. **kitty spawn on the Phase 6 target is ~67 ms** — roughly half the
   laptop's ~130-142 ms. Expected direction (much faster CPU dominates
   kitty's embedded-Python + EGL bring-up); the milestone/compositor
   differences make the ratio coarse.
2. **The glvnd ICD tax is asymmetric, and the 4090 box doesn't pay it.**
   Removing the *mesa* ICD from enumeration changed nothing (Δ ≈ 0 ms,
   overlapping distributions) — the useless-extra-vendor cost that ran
   7-12 ms for the heavyweight nvidia stack on the hybrid laptop
   (4.8b/4.9) is ~0 for the lightweight mesa stack on an NVIDIA-primary
   box. Consequence for the pending author decision: the mesa-ICD pin is
   a **laptop-only** optimization; the shipped desktop config needs no
   pin and must not carry one.

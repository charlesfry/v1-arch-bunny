# 4.19 — greetd measured (the number the display-manager re-rank was waiting on)

Overnight 2026-08-25, on `arch-bunny`. The 2026-08-21 re-rank said greetd's
"~2 MB" resident cost was unsourced and "that measurement is what closes
the slot." Instrument: `instruments/4.19-greetd.sh` (one sample per boot);
raw: `raw/4.19.greetd.log`. Config tested: greetd 0.10.3-2,
`default_session command="niri-session" user="bunne"` — the
autologin-forever shape (same as the NixOS box), **not** the
`initial_session`+greeter-after-logout shape the re-rank described; the
resident cost transfers (the greeter binary only runs after a logout;
`agreety` ships in the greetd package), but exit-behavior differs — noted
for the decision.

## Resident cost — the headline

**greetd runs as TWO resident processes totaling ~6.8 MB PSS**, stable
across both boots (supervisor 1,099/1,119 kB + session-holder
5,682/5,748 kB; `Restart=always`, so it is a permanent daemon, as the
re-rank suspected). The unsourced "~2 MB" was ~3× light. Open note (DA
round 16): both readings are minutes-old sessions; day-long growth of the
session-holder is unmeasured (small Rust daemon — bounded risk, stated).

## Boot delta — none detectable

| boot | config | userspace → graphical.target |
|---|---|---|
| 23:28 (post-flip) | getty-autologin | 3.244 s |
| 00:01 | greetd A | 2.906 s |
| 00:06 | greetd B | 2.690 s |

The within-config spread of autologin (0.54 s) exceeds any between-config
gap — **no boot penalty claim in either direction at n=2 vs n=2.** No
initramfs was regenerated tonight (discard rule not triggered).

## Functional checks, both greetd boots

niri session up first-try; IPC spawn canary PASS; mate-polkit agent
running. **Session class becomes `greeter`** (getty path: `user`) — same
as the NixOS box. Two consequences flagged for the decision: logind
refuses `SetLockedHint` for greeter-class sessions (cosmetic, seen on both
OSes), and portals/screen-sharing were NOT re-accepted under the greeter
class — if greetd is ever picked, re-run the C4 screen-share acceptance
under it before shipping.

## The decision this feeds (author's — both paths zero-prompt)

- **getty-autologin (current)**: 0 MB resident. On session exit, getty
  respawns → autologin → the `.bash_profile` guard re-execs niri — an
  ad-hoc session-restart loop with no greeter ever. **Tested, not just
  reasoned (DA round 16): `pkill -x niri` → fresh niri session up in
  <4 s, new pid, spawns working** (n=1, clean-kill shape; a crash-loop
  hits getty's restart limiting differently — untested).
- **greetd**: ~6.8 MB PSS forever + one package. Buys: a supervised
  session (`Restart=always`), and — in the `initial_session` shape — a
  real greeter on logout instead of an instant re-login.

Reverted after measurement: greetd **disabled but left installed**
(not rejected — the slot is undecided; the stale-loser rule applies at
decision time), box back on getty-autologin, canary-verified. The
recovery boot doubles as DA round 15's final control: fresh unlocked
session → IPC spawn works (locked → silently dropped, proven earlier the
same night).

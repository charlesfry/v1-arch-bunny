# Phase 3 checkpoint — the first *running desktop* measurements

Measured 2026-08-20 on `bunne-test`, all four runs on **one boot**, each with a
completely empty session (no terminal, no bar, no launcher, no wallpaper except
where noted) idled **>120s** before sampling.

This closes the largest unmeasured number in the project. Every checkpoint
before this one — [`2.1.base.md`](2.1.base.md),
[`3.1.audio-bluetooth.md`](3.1.audio-bluetooth.md) — was TTY-idle with no
compositor running, so the cost of a live session was unknown.

Captured with `~/t-idle <label>`, a fairness gate wrapping `~/t-benchmark`. The
gate refuses to measure if two compositors are up, if trial clients (kitty,
waybar, fuzzel…) are running, or if the compositor has been up less than 120s.
It exists because earlier informal numbers were polluted by exactly those things.

## Headline: niri's idle session costs 88 MB, Hyprland's costs 214–267 MB

| run | used (procps) | delta vs baseline | compositor RSS |
|---|---|---|---|
| baseline, no compositor | 603.6 MB | — | — |
| **niri** | **691.3 MB** | **+87.7 MB** | 205 MB (+43 MB spawner) |
| Hyprland, stock | 870.2 MB | +266.6 MB | 342 MB + Xwayland 246 MB |
| Hyprland, wallpaper + Xwayland off | 817.6 MB | +214.0 MB | 341 MB |

**niri is ~126 MB leaner like-for-like.** The fourth run exists to answer the
obvious objection — that niri only looks lean because it ships less desktop. It
does ship less, but that is not the explanation: with Hyprland's wallpaper and
Xwayland both disabled, so that both compositors draw a bare backdrop and
neither has an X11 server, Hyprland still costs 2.4× what niri does.

Use the `used (procps)` column, not RSS. RSS double-counts shared pages badly
here, and this run demonstrates it: removing Xwayland (**246 MB of RSS**) and
the wallpaper together freed only **52.6 MB** of real memory.

## Two findings that only appear with a session running

**Hyprland starts Xwayland eagerly.** 246 MB RSS, resident, with zero X11
clients on the machine — `pgrep -c Xwayland` returns 0 only after
`xwayland { enabled = false }`. This inverts the usual framing of "Hyprland has
built-in Xwayland, niri needs `xwayland-satellite`": Hyprland's is *always* paid,
niri's is on-demand (its binary carries a `--test-listenfd-support` probe and
spawns the satellite only when an X11 client appears). See `CHOICES.md`
`compositor`.

**niri forks a helper named `Command Spawner`** (PID child of niri, 43 MB RSS,
mostly copy-on-write shared with its parent — which is why the `free` delta is
88 MB and not 88+43). It also leaves a `<defunct>` child of that helper unreaped.
Harmless — a zombie holds a PID table entry, not memory — but it is there.

## Session structure differs

| | niri | Hyprland |
|---|---|---|
| user units running | 4 (`niri.service`, `dbus-broker`, `dbus.socket`, `init.scope`) | 3 (no unit at all) |
| systemd-managed | yes — `niri-session` runs `systemctl --user --wait start niri.service` | no — `start-hyprland` execs the binary directly |

niri's session is a real systemd user service with `graphical-session.target`
bound correctly; Hyprland's is not. That matters for anything ordered against
`graphical-session.target` later (idle, lock, portal, bar).

Both add `polkit` (9 MB) to the system service count, woken by the session.
System services 13 → 14 in both cases. Zero failed units throughout.

## Not measured here

- **Boot time is identical across all four**, because they share one boot —
  `graphical.target` 2.240s. Compositor launch time is *not* captured by
  `systemd-analyze`; a separate test would be needed.
- **No window was ever opened.** This is the floor, not a working desktop. The
  cost of kitty + a bar + a launcher is still unknown for either.
- The laptop runs `sshd` (a deviation, `CHOICES.md` `ssh`), costing 28.6 MB
  across 3 processes in every run above. It is constant, so it cancels in the
  deltas, but subtract it for an absolute figure.

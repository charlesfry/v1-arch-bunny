# 4.20 — dir-aware-display: the prototype exists and the hot path is free

Overnight 2026-08-25. The `dir-aware-display` row's recorded design,
built and measured: `instruments/4.20-diraware.sh` (prototype + its own
benchmark, ~25 shippable lines), raw `raw/4.20.diraware.log`.

Shape, exactly as the row specified: a user-editable mapping file
(`~/.config/bunne/dirmap.conf`, `prefix<TAB>name<TAB>ansi-color`) loaded
once at shell start; a `PROMPT_COMMAND` hook whose first line is a single
`[[ $PWD == $last ]] && return` gate; on directory change it prefix-matches
the map, sets the kitty window/tab title (`OSC 2`, `[work] ~/tradeswell/…`)
and a prompt-color variable. **Bash builtins only — zero forks on every
path, including the change path.**

| path | cost | context |
|---|---|---|
| every prompt, dir unchanged | **9.3 µs** (n=100k calls) | 0.1% of the shipped 8.4 ms prompt; ~bash function-call overhead itself |
| on cd, profile match | 32.8 µs | fires only on directory change |
| on cd, no match (full scan, 3-entry map) | 37.2 µs | worst case |

Functional demo in the log: work/oss/scratch/default profiles all matched
correctly, including nested paths and the exact-prefix edge.

Notes for the row (author's call remains — the row stays `deferred`):

- **Tab *color*** (as opposed to title) is the one part that cannot be
  fork-free: kitty only exposes it via remote control
  (`kitten @ set-tab-color`), which needs `allow_remote_control` in
  kitty.conf and forks a kitten per cd. A fork on cd (not per prompt) is
  arguably fine — but it is a config surface + a fork, so it ships only if
  the author wants the color specifically; title + prompt color are free.
- The **direnv half** of the row (real env vars in `.envrc`) is untouched
  here and unchanged from the row's design; remember BUDGET's lesson —
  direnv's stock `_direnv_hook` cost 15 ms/prompt ungated; if direnv
  ships, its hook wants the same changed-dir gate this prototype uses.
- Measured over ssh/bash on the idle box; the numbers are CPU-only
  (EPOCHREALTIME deltas, no terminal in the loop) — the OSC write itself
  is a single printf to the pty.

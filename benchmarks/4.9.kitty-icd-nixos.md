# 4.9 — does NixOS kitty pay the same glvnd nvidia-ICD tax? (resolves 4.2's open confound)

`arch-bunny` + NixOS side, 2026-08-24. Follow-up demanded by 4.8b DA round
1 #8 / round 2 #3: 4.2's kitty gap (~23 ms) compared untaxed Arch against
NixOS, and whether NixOS's kitty even pays the glvnd nvidia-ICD tax was
unverified. NixOS's `/run/opengl-driver/share/glvnd/egl_vendor.d/`
contains both `10_nvidia.json` and `50_mesa.json` (verified today), so
glvnd there has the same two vendors to enumerate.

## Pre-registered (committed before execution)

Protocol: NixOS 26.05, nvidia-open (as it has run since 2026-08-22 — the
driver is NOT new on this side, so NixOS cross-night envelopes are
internally consistent). Two fresh boots, block-interleaved
`spawnbench.py 5 kitty,kitty-mesa-nixos,kitty,kitty-mesa-nixos,fuzzel`
(boot A) and mesa-first (boot B) — same instrument and shape as the
DA-cleared 4.8b, warm n=8/arm/boot. Per boot: boot id + uptime + power
state deposited; maps probe per arm (count + names) and fuzzel maps
count; all stdout tee'd verbatim to `raw/4.9.kitty-icd-nixos.jsonl`.

Decision rule:
- **NixOS pays the tax** if, on BOTH boots, (default − mesa-pinned) warm
  median ≥ 5 ms AND default kitty maps nvidia libraries while the mesa
  arm maps none.
- **NixOS does not pay it** if the delta is < 2 ms on both boots with the
  maps asymmetry still present (enumeration cheap there for some reason).
- Between 2-5 ms or discordant boots: unresolved, report only.
- Boot-colds recorded, n=1 per arm, characterization only, no claim (4.8b
  lesson: colds sit on a warmup curve).
- Controls: fuzzel warm median vs the NixOS side's 2026-08-23 envelope
  (21.9 / 22.4) — same stack both nights, so a shift flags environment
  drift; it does not void the within-boot A/B.
- If the tax is confirmed, the 4.2 annotation may state: both OSes pay a
  driver-stack tax; a symmetric-stack warm comparison is
  (Arch default post-nvidia: 140.0-142.7 across 6 boots, 4.8/4.8b) vs
  (NixOS default: tonight's medians) — same instrument, same day, cross-OS,
  and THAT number goes to DA before entering 4.2.

## Results (raw: `raw/4.9.kitty-icd-nixos.jsonl`, deposited verbatim)

Two fresh boots (ids `cdfae9f6…`, `c3784973…`, uptime ~80 s at start, AC
power, NixOS kernel 6.18.x, nvidia 595.71.05 — note the driver is an
older major than Arch's 610.57.04, a confound on tax-*size* comparisons).

| boot | pooled default warm median (n=8) | pooled pinned warm median (n=8) | Δ |
|---|---|---|---|
| A | 156.3 | 144.25 | **12.0** |
| B | 154.0 | 143.9 | **10.1** |

Block deltas: 13.8 / 10.8 (boot A), 11.0 / 0.9 (boot B). Per DA: the
boot-B anomaly is **two contaminated runs** (153.9, 162.2 — inside the
default arm's range, load1 0.25-0.27 so not load) among the pinned arm's
n=8, not "one wild block"; the pooled median dilutes them, it does not
launder them. Direction of the contamination: it *understates* the tax
(conservative) and *overstates* the pinned-vs-pinned OS gap by ~0.6 ms.
fuzzel control: 21.75 / 21.85 vs the NixOS side's 2026-08-23 values
21.9 / 22.4 — technically below that envelope's low end; calling this
"no drift" is a judgment call against an n=2 envelope and is labeled as
such. (Helping observation, per DA: fuzzel flat-to-faster while kitty is
slower localizes the cross-OS gap to kitty's launch path, not the
session environment.)

**Maps evidence — three defective probe generations disclosed, then a
clean one.** (1) The in-run probes deposited pids (2843-2917) but empty
`/proc` reads — `pgrep -f kitty` matched a transient/exited process (the
write-up's first "empty pid" description was itself wrong; corrected per
DA). (2) Those broken probes killed the wrong pids, orphaning kitty
windows — which then poisoned the next two probe generations by getting
selected as stale windows: PROBE-FIX's "default" (pid 2864, older than
the probes before it — the deposit's own pid ordering proves staleness)
produced the inverted result, and the "controlled reprobe"'s `default1`
(pid 2812) was likewise stale, so its claimed D-P-P-D interleave was
really **1 fresh default + 2 fresh pinned + stale windows**. What
survives from those probes, on pid-ordering evidence rather than
narrative: every environ-verified unpinned kitty maps 51 nvidia entries;
every environ-verified pinned kitty maps 0. (3) The clean probe
(PROBE-C in raw): fresh boot, wall-clock and journal anchors deposited,
a single-kitty-window invariant asserted before every read, environ
verified per process — results below.

## Verdict (DA round 1: survives with caveats; fixes applied in place)

**Honest rule accounting (per DA #1): the pre-registered rule as written
did NOT fire** — its maps conjunct demanded evidence on both boots, and
boot A had none. What the evidence supports: the *timing* condition met
on both boots (Δ = 12.0 / 10.1 ms, both ≥ 5); the *mechanism* condition
verified post-hoc on boot B and on one additional fresh boot (PROBE-C,
demanded by DA before the 4.2 annotation could land). Conclusion entered:
**NixOS kitty pays the same glvnd nvidia-ICD tax, roughly 10-12 ms per
warm launch on driver 595.71.05** — tax *size* is not transportable to
other driver versions (Arch's 610 measured 7-10 ms enumerating a
same-shaped stack).

PROBE-C, deposited (fresh boot `ca33a069…`, 2026-08-24T10:16, journal
head anchored, `preexisting_kitty_windows=[none]`, single-window
invariant asserted before each read, ascending fresh pids 1981→2031):
**default — pin absent from environ, 51 nvidia maps; pinned — pin
present, 0 maps.** Mechanism now verified on two distinct boots with
clean protocol on one and pid-ordering-validated evidence on the other.

Symmetric readouts, coarsened per DA #6/#7 (same instrument, same
hardware, same day; **2 NixOS boots vs 5 Arch boots** — 4.8's 3 fresh
boots + 4.8b's 2, mixed per-block/pooled median estimators, hence coarse
quoting only):

- default vs default (both OSes taxed): Arch ~140-143 vs NixOS ~154-156
  → **roughly 10-15 ms**.
- pinned vs pinned (enumeration removed on both): Arch ~132-134 vs NixOS
  ~144 → **roughly 10-12 ms of as-shipped OS difference**, attributable
  to any of: kitty wrapper exec, store-path linking, build flags, AND the
  kernel generations (Arch 7.1.9 vs NixOS 6.18.44) and resident driver
  majors — the kernel confound is named per DA; do not attribute this to
  Nix packaging mechanisms specifically without isolating it.

So 4.2's original ~23 ms kitty gap was ≈ NixOS's ICD tax stacked on a
roughly 10-12 ms as-shipped OS gap, measured against a then-untaxed
Arch. Arch remains faster; the margin specific to OS choice is about
half of what 4.2's table suggested.

Measured 2026-08-18 on the test laptop (Intel Coffee Lake-H i7, GTX 1660 Ti

against: vanilla Arch, encrypted, dual-booting, NVIDIA driver working, firewall

## Boot

```
firmware   4.801s
loader     1.301s
kernel     5.988s   <-- NOT A VALID METRIC, see below
userspace  2.096s
graphical.target reached after 2.095s
```

**Only `userspace` / `graphical.target` is comparable across boots.** The
`kernel` figure includes the LUKS passphrase wait, i.e. human typing speed — it
was measured at 30.026s and 5.988s on two consecutive boots with no config
change affecting that phase. Never quote total boot time from this machine while
it prompts for a passphrase. (If TPM2 auto-unlock is adopted later, totals
become meaningful and this caveat can be dropped.)

`loader` is Limine's menu timeout, set to `1`. It was `3` (and briefly `60`).

**Headline: `graphical.target` at 2.095s, against the Omarchy baseline's 5.07s.**
Not yet apples-to-apples — Omarchy was running a full desktop — but this is the
number to keep honest as Phase 3 adds things back.

## Idle RAM

**599 MB used** of 15829 MB, 236 MB buff/cache. Genuinely idle: no desktop, no
user services running, one SSH session.

> **Two caveats added 2026-08-19, after investigating what this number contains
> (see [`3.1.audio-bluetooth.md`](3.1.audio-bluetooth.md) for the full working).**
> The "one SSH session" inflates this by **~28 MB**, and `sshd` is not shipped
> enabled by BunnE — the test laptop is a deviation. And `free`'s `used` column
> is `MemTotal - MemAvailable` in procps 4.x, so ~260 MB of it is kernel reserve
> rather than consumption; real usage by the classic definition is ~330 MB, of
> which ~185 MB is kernel (slab, modules, page tables) that no amount of
> daemon-trimming can touch. This figure is still valid *as a comparison* with
> later checkpoints measured the same way — just do not read it as "599 MB of
> things are running."

## The kitty-launch question (author asked: NixOS was ~170 ms; beat it, no single-instance hacks)

**Answer: Arch already runs kitty at ~130 ms warm — 15% faster than NixOS's
153-155 ms measured tonight with the same instrument on the same hardware —
and ~130 ms is kitty-intrinsic on this machine. There is no honest config
lever left:**

- **Our config costs nothing:** `--config NONE` is statistically identical
  (132.4 vs 131.7 median). Fragment Mono + `disable_ligatures always` add
  zero startup cost. fc-match resolves the font in 6-10 ms warm (cached).
- **Exec/link floor is 2 ms** (`kitty --version` ×3) — the ~130 ms lives in
  real bring-up: embedded-Python init, EGL/GL context + glyph atlas setup,
  Wayland registry — kitty architecture, not our configuration.
- The banned lever is the only big one: single-instance/daemon modes
  (`--single-instance`, `kitten quick-access-terminal`, foot's `--server`
  analog) — excluded by the author for stability.
- Cross-OS: the NixOS gap (warm +23 ms, cold +80 ms) sits in kitty's own
  bring-up there (nix wrapper exec, store-path linking, build differences);
  fuzzel — identical on both OSes — clears the compositor/spawn path.
- Perception note: niri's window-open animation (~150 ms default ease)
  overlaps the map; perceived "terminal is there" ≈ map time, with the
  animation masking part of it. Keystroke-to-photon still needs the
  high-speed-camera step (04-plan Phase 1 step 4); unchanged.

## Side findings, each with a next action

1. **nouveau is loaded on the unused dGPU** (card2/renderD129 live) with no
   firmware installed — it cannot reclock, which on Turing-class laptops
   typically means the dGPU idles hot instead of sleeping. Candidates:
   blacklist nouveau on this box (test-box deviation) or install the real
   driver. Author call; measurable battery/boot deltas either way.
2. **vapoursynth's profile.d is back** (via `ffmpeg`) on a fresh install,
   and `ffmpeg` arrives through **`localsearch`** (GNOME's indexer, dragged
   by the portal chain) — `bash -lc true` = **75-76 ms** (×3), replicating
   3.8's 74.1 ms almost exactly. Row 71's "leave it alone" reasoning holds;
   the row should note the dependency path and that the cost is per login
   shell.
3. `localsearch` itself is new audit surface nobody chose (portal-gnome →
   localsearch → ffmpeg → vapoursynth chain) — not resident in tonight's
   PSS tables, but its service/timer surface deserves a look in the
   `portal` row's spirit of "nobody chose this."
4. mkinitcpio 41 ships `PRESETS=('default')` — no fallback initramfs
   anymore; docs assuming `initramfs-linux-fallback.img` are stale.

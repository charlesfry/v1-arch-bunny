# Phase 3 — attacking the two per-interaction costs

> ### ⚠ Measurement caveat — the desktop is not a quiet machine
>
> Added 2026-08-21 at the author's prompting, and **verified**: the Omarchy
> desktop is his working machine and runs CPU-heavy ML training while this hobby
> project is being worked on. At the time these numbers were taken it showed
> **load average 32.5 on 24 cores**, with four `python3` processes at ~600% CPU
> each. Every desktop figure here is inflated.
>
> **Measured inflation**, same primitives on the idle laptop:
>
> | primitive | desktop (load 32.5) | idle laptop | ratio |
> |---|---|---|---|
> | bash function call | 0.201 ms | 0.089 ms | 2.3x |
> | one `$( )` subshell | 2.977 ms | 1.023 ms | 2.9x |
> | one `$( /bin/true )` fork | 5.298 ms | 2.103 ms | 2.5x |
>
> **The inflation is roughly uniform (2.3-2.9x), so relative comparisons and
> every conclusion drawn from them survive; the absolute numbers do not.** Divide
> desktop figures by ~2.5 for an unloaded estimate. Note this bias *flatters* the
> fork-free recommendations, since forking suffers more under contention than
> pure-bash work does — which is the case for reading them sceptically, not
> credulously. A second confound: the laptop's environment is 406 bytes / 17 vars
> against the desktop's 9950 / 226, and subshell cost scales with environment
> size, so a lean BunnE gets cheaper subshells for free.
>
> **Rule going forward: record `uptime` alongside any timing taken on the
> desktop, and prefer the laptop for absolute numbers.**


Measured 2026-08-21 on the Omarchy desktop (Ryzen 9 7900X). Follows
[`3.4.shell-startup.md`](3.4.shell-startup.md), which established that the real
costs are tier 2 (per terminal) and tier 3 (per prompt), both in files BunnE
writes from scratch.

**Headline.** Terminal startup **317 ms → 19 ms**. Per-prompt **65.7 ms →
1.5 ms** (or 12.5 ms keeping a dirty-state marker). Nothing here is a trick; it
is removing eager work and command substitution.

| | Current | Candidate | Factor |
|---|---|---|---|
| New terminal (`bash -ic exit`) | 317.5 ms | **19.1 ms** | **16.6×** |
| Per prompt, branch only | 65.7 ms | **1.5 ms** | **45×** |
| Per prompt, with dirty marker | 65.7 ms | **12.5 ms** | **5.3×** |

Floor for reference: bare `bash --noprofile --norc` is 9.3 ms, so the candidate
`.bashrc` adds ~10 ms where Omarchy's adds ~308 ms.

## Where the per-prompt 65.7 ms went

| Component | Cost | Fix |
|---|---|---|
| `starship prompt` | 35–43 ms | replace with bash (below) |
| `_direnv_hook` | 15.0 ms | gate on `$PWD` change → **0.23 ms** |

**direnv was invisible until measured.** `PROMPT_COMMAND` on the desktop is
`_direnv_hook` and nothing else, so direnv forks `direnv export bash` after
*every command*. Gating it on an actual directory change costs 0.23 ms and still
fires on `cd` — verified. This is precisely the pattern `02-functionality.md` C5
already prescribes for dir-aware display: *"a plain string compare against `$PWD`
in `PROMPT_COMMAND`... with any expensive call gated behind that change."* It was
written for one feature and applies to every prompt hook.

**Tradeoff, stated:** gated direnv will not notice an edited `.envrc` until the
next `cd`. `direnv reload` covers that, and editing `.envrc` is rare compared to
running commands.

## The prompt replacement

`starship.toml` renders `directory · git_branch · git_status · character`. The
candidate reproduces that layout. **Design rule: no command substitution anywhere
on the prompt path** — a bare `$( )` subshell measured **2.98 ms** on this box
(inflated by a 226-variable, 9950-byte environment), which is more than the whole
rest of the prompt. Helpers assign to globals instead of echoing.

Measured primitives, for anyone tempted to "just add one more thing":

| Operation | Cost |
|---|---|
| bash function call | 0.20 ms |
| read a file with `read <` | 0.37 ms |
| **one `$( )` subshell** | **2.98 ms** |
| one `$( /bin/true )` fork+exec | 5.30 ms |
| one `git` fork | ~6 ms + git's work |

Branch detection walks up to the repo root and reads `.git/HEAD` directly — zero
forks, and **independent of repo size**:

| Repo | Files | starship | candidate (full) | candidate (fast) |
|---|---|---|---|---|
| arch-bunny | 244 | 37.7 ms | 10.7 ms | **0.65 ms** |
| walls | 1719 | 42.9 ms | 17.8 ms | **0.58 ms** |

Verified correct at repo root, in a subdirectory, and outside any repo; handles
detached HEAD (short sha) and `.git`-as-a-file (worktrees/submodules).

### Correction — `diff-index` was the wrong choice

The original design used `git diff-index --quiet HEAD --` to avoid a subshell.
**Measured on the idle laptop, that was wrong on both counts.** 1736 tracked
files, 56 directories, caches warm:

| Prompt variant | Cost |
|---|---|
| branch only, zero forks | **0.10 ms** |
| + `diff-index` dirty marker (no untracked detection) | 13.84 ms |
| + `git status --porcelain` dirty marker (**with** untracked) | **8.19 ms** |
| + `git status`, junk-heavy repo, file-pattern ignore | 12.82 ms |
| ... same, plus `core.untrackedCache` | 10.16 ms |

**`git status` is faster than `diff-index` *and* detects more.** The subshell
being avoided costs ~1 ms idle, while `diff-index` compares the working tree
against HEAD and re-checks content that `git status` short-circuits through the
index's stat cache. **Use `git status --porcelain`.** The "no command
substitution" rule still holds everywhere else on the prompt path — it is worth
2–3 ms — but it does not justify a slower git invocation.

### How much does repo mess actually cost?

An earlier draft claimed untracked scanning "scales with repo size" and cited
`walls` at 98.7 ms. **That figure was a cold-cache first run.** Re-measured warm
on the same machine under the same load: **20.8 ms**. And `walls` turns out to
have 1719 tracked files, **zero** untracked entries, 56 directories and no
`.gitignore` at all — nothing that could have driven the number claimed.

The real curve, idle laptop, growing an untracked tree:

| dirs | files | `git status` |
|---|---|---|
| 50 | 250 | 2.48 ms |
| 200 | 1 000 | 6.46 ms |
| 800 | 4 000 | 5.22 ms |
| 3 200 | 16 000 | **4.65 ms** |

**Essentially flat.** Git collapses a wholly-untracked directory into a single
entry without descending into it, so thousands of junk directories cost almost
nothing. Directory *count* is not the variable.

**What actually costs, and it is worth knowing:** how `.gitignore` is written.
Identical trees, 3200 dirs / 16000 files:

| ignore style | cost |
|---|---|
| directory ignore (`junk/`) | **4.03 ms** |
| file-pattern ignore (`*.tmp`) | **36.30 ms** |

A directory pattern lets git skip an entire subtree unread. A file pattern forces
it to descend everywhere and test every filename. **9x, for a `.gitignore`
style choice** — prefer `__pycache__/` over `*.pyc`, `node_modules/` over
`*.js.map`. This is advice for repos generally, not just for the prompt.

`core.untrackedCache = true` recovers part of the file-pattern penalty (12.82 →
10.16 ms) and needs no daemon; it memoises the per-directory scan against
directory mtime, and `git update-index --test-untracked-cache` reports OK on
btrfs here. **`core.fsmonitor` remains rejected**: it is marginally faster again
but starts a resident `git fsmonitor--daemon` per repository, which priority 2b
refuses. Confirmed spawning, then stopped.

## mise: 143 ms → 0.75 ms

`mise` manages exactly one thing here — `node = "25.1.0"` in
`~/.config/mise/config.toml`.

| Approach | Cost per terminal |
|---|---|
| `eval "$(mise activate bash)"` | **143.5 ms** |
| `PATH=$HOME/.local/share/mise/shims:$PATH` | **0.75 ms** |

Shims verified working: `node --version` → `v25.1.0`, resolving through
`~/.local/share/mise/shims/node`. 190× cheaper for the same result. Shims resolve
the version at exec time, so per-directory pinning still works; what is lost is
`activate`'s environment munging, which nothing here uses.

## The pattern worth generalising

`conda.sh` costs **0.3 ms** because it defines a function and defers the 2341 ms
`conda shell.bash hook` until `conda activate` runs. Every other integration
measured here does its expensive work eagerly at shell start. **Prefer: define,
defer, and gate on change.**

## Candidate code, for review — not deployed

```bash
: "${BUNNE_PROMPT_GIT_STATUS:=1}"

_bunne_find_repo() {                       # -> _BR ; no subshell, no fork
	local d=$PWD
	_BR=
	while [[ $d == /?* ]]; do
		if [[ -e $d/.git ]]; then _BR=$d; return; fi
		d=${d%/*}
	done
	[[ -e /.git ]] && _BR=/
}

_bunne_read_branch() {                     # -> _BB ; one file read
	local h
	_BB=git
	[[ -r $_BR/.git/HEAD ]] || return
	read -r h <"$_BR/.git/HEAD" || return
	case $h in
	ref:*) _BB=${h##*/} ;;
	*) _BB=${h:0:7} ;;
	esac
}

_bunne_prompt() {
	local rc=$? dirty='' tail
	_bunne_find_repo
	if [[ $_BR ]]; then
		_bunne_read_branch
		tail=${PWD#"$_BR"}
		if ((BUNNE_PROMPT_GIT_STATUS)); then
			# git status, not diff-index: measured faster AND catches untracked.
			local o; o=$(git status --porcelain 2>/dev/null)
			[[ $o ]] && dirty=' ●'
		fi
		PS1="\[\e[1;36m\]${_BR##*/}${tail}\[\e[0m\] \[\e[3;36m\]${_BB}\[\e[0m\]\[\e[36m\]${dirty}\[\e[0m\] "
	else
		PS1='\[\e[1;36m\]\w\[\e[0m\] '
	fi
	if ((rc)); then PS1+=$'\[\e[1;36m\]✗\[\e[0m\] '; else PS1+=$'\[\e[1;36m\]❯\[\e[0m\] '; fi
}

_bunne_direnv() {                          # gate the fork on a real cd
	[[ $PWD == "$_BUNNE_LASTPWD" ]] && return
	_BUNNE_LASTPWD=$PWD
	_direnv_hook
}
```

`shellcheck`-clean. Colours are hardcoded here for measurement only — in the real
config they come from the palette file (`02-functionality.md` C10).

## Open for the author

1. **Does the prompt show a dirty marker at all?** This is now the only real
   question, and it is stark: **0.10 ms without, 8.2 ms with** (12.8 ms in a
   junk-heavy repo). The marker costs ~80x the entire rest of the prompt. It is
   still ~2x cheaper than starship, which did the same job for 35–43 ms under
   load. Per `CLAUDE.md` this gets *decided*, not shipped as a knob.
2. **`core.untrackedCache = true` globally?** Worth ~2.7 ms only in repos with
   file-pattern ignores; no daemon, slightly larger index file.
3. The untracked-vs-not question **has dissolved** — `git status` is both faster
   than `diff-index` and more complete, so there is nothing to trade.
